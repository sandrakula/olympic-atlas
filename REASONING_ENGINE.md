# Интеллектуальный поиск OLYMPIC ATLAS

`/explore` выполняет полнотекстовый поиск и отвечает на вопросы о записях SQLite. Правила вычисляют результат из существующих отношений Prisma. Внешние модели и сетевые запросы к источникам не требуются. Цитаты ссылаются на сохранённые документы.

```mermaid
flowchart LR
  Q["Вопрос пользователя"] --> I["Распознавание намерения"]
  I --> E["Извлечение сущностей"]
  E --> D["Запрос к базе знаний SQLite"]
  D --> R["Применение правила"]
  R --> S["Чтение цитат и проверка цепочки"]
  S --> A["Ответ, ограничения и ссылки"]
```

## Компоненты

| Модуль | Назначение |
| --- | --- |
| `src/lib/repositories/explore-search.ts` | Поиск документов и ограниченная выборка кандидатов |
| `src/lib/explore/interpret.ts` | Распознавание намерения и извлечение параметров по шаблонам |
| `src/lib/explore/question-corrections.ts` | Предлагает подтвердить исправление формулировки или сущности |
| `src/lib/explore/resolve.ts` | Привязка названий, имён и годов к идентификаторам SQLite |
| `src/lib/explore/rules.ts` | Выполнение десяти правил на исходных таблицах |
| `src/lib/explore/answer.ts` | Формирование ответа, статуса, фактов, цитат и ссылок |
| `/api/explore` | Ограниченный API для вопросов и полнотекстового поиска |

При неточном вводе SMART SEARCH 2.0 предлагает исправление. Например, «На каких олимпидах выступала Симона Байлс?» можно заменить на «На каких олимпиадах выступала Симона Байлз?». После подтверждения выполняется то же правило участий и проверяется происхождение фактов. Точные алиасы учитываются при разрешении сущности. Опечатки, транслитерация и неправильная раскладка требуют подтверждения. При нескольких точных совпадениях ответ запрашивает уточнение. [Архитектура поиска и результаты проверки](./SMART_SEARCH.md)

## Правила и ответы на рабочей базе

| Вопрос | Связь или операция | Результат в текущей базе |
| --- | --- | --- |
| Какие Игры проходили в Италии? | `OlympicEdition.hostCountryId`, статус `HELD` | Кортина 1956, Рим 1960, Турин 2006, Милан и Кортина 2026 |
| Какие спортсмены участвовали в Рио-2016? | `OlympicEdition ← Participation → Athlete` | 4 профиля с записанными участиями |
| Кто получил золото в беге на 100 м в Париже-2024? | `Edition ← Event ← MedalResult → Athlete / Team` | Жюльен Альфред |
| Какие медали получил Майкл Фелпс? | `Athlete ← MedalResult` и `Athlete ← TeamMember → Team ← MedalResult` | 6 записей, учитываемых в базе |
| На каких Играх выступала Симона Байлз? | `Athlete ← Participation → OlympicEdition` | Рио-де-Жанейро 2016, Токио 2020, Париж 2024 |
| Какие виды спорта представлены в издании 2012 года? | `Event → Discipline → Sport` и `Participation → Sport` | Лёгкая атлетика и плавание в детальной выборке |
| Кто представлял США на Играх Рио-2016? | `Participation.editionId` и `Participation.nocId` | Майкл Фелпс и Симона Байлз |
| Кто выигрывал золото на нескольких Играх? | `COUNT(DISTINCT Event.editionId) >= 2` для золотых медалей спортсмена | Майкл Фелпс и Усэйн Болт |
| Какие страны проводили летние Игры? | Группировка состоявшихся летних изданий по `hostCountryId` | Страны и число их изданий в каталоге |
| Сколько зимних Игр состоялось до 2026 года включительно? | Подсчёт по `HELD`, `WINTER` и официальному году издания | 25 |

Один факт участия хранит спортсмена, издание, вид спорта и НОК. Гражданство или биографическая привязка не участвуют в правиле представительства. У командной медали один `MedalResult` и один владелец `Team`. Пара «результат, спортсмен» проецируется через уникальную запись состава команды. Несколько наград на одних Играх дают одно издание в правиле нескольких Игр.

## SQLite FTS5

Миграция `20261122000000_atlas_search_fts5` создаёт производный индекс `AtlasSearch` и заполняет его из существующей базы. В срезе 515 документов. Индекс включает спортсменов, издания, страны, НОК, виды спорта, дисциплины, соревнования и источники. Индексируются имена, псевдонимы, города, годы, коды, короткие описания и биографии.

Токенизатор `unicode61` обрабатывает кириллицу и латиницу без учёта регистра. Форма поиска принимает начала слов. Например, «Майкл Фел» находит Майкла Фелпса. Английское написание работает, когда присутствует в имени, псевдониме или URL-идентификаторе. В разрешении вопросов есть небольшой словарь вариантов вроде «Италии» → `ITA` и «Париже» → `paris`. Общего морфологического анализа и автоматической транслитерации нет.

Ранжирование BM25 повышает вес названия и псевдонимов. Страница содержит до 10 совпадений. Результаты получают ссылки и метаданные исходных объектов через репозиторий графа. SQLite-триггеры синхронизируют индекс после `INSERT`, `UPDATE`, `DELETE` и повторного импорта через upsert. В следующей миграции с пересозданием одной из индексируемых таблиц её триггеры нужно восстановить.

## Объяснение и неполнота

Ответ включает идентификатор правила, найденные объекты, шаги вывода, строки-основания и цитаты. `FactCitation` связывает запись и поле с `KnowledgeSource`. Участие подтверждает поле `participation`, медальный результат — `result`, а основные сведения об издании — `core`. Исторические числа в аналитике требуют отдельной цитаты каждого поля. Добавленные результаты Болта и Маршана доступны существующим правилам. В SQLite после сверки 530 документов FTS5.

Кнопка «Цепочка в графе» переносит идентификаторы фактических рёбер из правила. Граф проверяет существование и непрерывность цепочки и подсвечивает её. Для вывода о золоте на нескольких Играх объяснение приводит две записи-свидетельства, а одна ссылка показывает путь к первой из них.

Интерфейс различает неподдерживаемый вопрос, несуществующий или неоднозначный объект, объект без связанных записей, частичный ответ и полный подсчёт по каталогу. Полнота подсчёта относится к проверенному каталогу состоявшихся изданий 1896–2026. Детальные данные об участиях, соревнованиях и медалях остаются частичными. Отсутствующая запись означает недостаточное покрытие.

Вход ограничен 240 символами, тело API — 4096 байт, полнотекстовое выражение — 12 токенами, поисковая выдача — 50 страницами, логический ответ — 20 строками и 60 фактами. SQL содержит фиксированные шаблоны и связанные параметры. Операторы FTS из пользовательской строки не выполняются. История из пяти запросов хранится в `sessionStorage` вкладки.
