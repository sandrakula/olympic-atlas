# Готовность OLYMPIC ATLAS к размещению

Приложение собирается как Next.js Node.js-сервер. Для стенда с текущим стеком нужен один экземпляр приложения с постоянным диском для SQLite. Публикация и выбор провайдера остаются отдельным шагом.

## Конфигурация

| Параметр | Назначение |
| --- | --- |
| `DATABASE_URL` | `file:./dev.db` и отсутствие переменной указывают на `prisma/dev.db`. На сервере задайте абсолютный `file:` URL к SQLite на постоянном диске |
| `ATLAS_SITE_URL` | Реальный публичный HTTP(S) origin, без пути и учётных данных. Служит основой для canonical, Open Graph, sitemap и robots. Без origin среда запрещает индексацию |
| `PORT` | Порт Node.js за HTTPS-прокси. По умолчанию 3000 |
| `ATLAS_E2E_CHANNEL` | Необязательный локальный канал Playwright, например `msedge`. На публичном сервере не нужен |

Для Prisma 7 поставьте зависимости с нативным `better-sqlite3` для целевой ОС, явно выполните `npm run db:generate` и проверьте `npm run db:validate`. Prisma CLI, сервер, seed и скрипты импорта используют общий путь SQLite. Сборку и runtime запускайте с публичным origin. Файл базы, `.env`, рабочие журналы и кэш сборки храните вне публичного каталога.

## Варианты среды

1. **Один Node.js-процесс на VPS или контейнере с постоянным томом.** Этот вариант сохраняет SQLite, FTS5 и запросы аналитики. Нужно обеспечить права на каталог базы, резервное копирование SQLite и проверку восстановления. Обычно HTTPS завершает обратный прокси.
2. **Реплицируемый или serverless-вариант.** Для независимых экземпляров понадобится общее хранилище и перенос модели, миграций, поиска FTS5 и специфичного SQLite SQL. Смена `DATABASE_URL` сама по себе не меняет провайдер и драйвер. Стандартный Vercel deployment не предоставляет постоянный локальный диск для файла базы. [Vercel о постоянном хранилище](https://vercel.com/i/can-you-run-docker-compose-on-vercel)

## Наполнение базы на сервере

- Чтобы перенести текущие 310 профилей с сохранением идентификаторов, создайте согласованную копию SQLite штатным backup API и доставьте её по закрытому каналу в каталог постоянного тома. Сверьте контрольные суммы и перечень таблиц. Копия файла из работающей базы в режиме WAL может пропустить изменения.
- Для чистой установки выполните `npx prisma migrate deploy` и `npm run db:seed`. Seed создаёт исходный каталог, справочники и проверенную выборку, включая точечный пакет этапа №9. Для воспроизведения широкого слоя профилей нужна копия актуальной базы или отдельный контролируемый импорт Wikidata/Commons.
- Для существующей версии примените `npx prisma migrate deploy` и `npm run db:release-audit`. Пакет сверки идемпотентен. Проверьте `PRAGMA integrity_check`, `PRAGMA foreign_key_check` и `npm run db:status`.
- Запустите `npm run build`, `npm start`, затем проверьте HTTPS, доступность favicon, canonical, robots/sitemap и резервный образ. HTTP 404, отсутствие серверных stack traces и типичные вопросы поиска проверяются локальным набором QA.

## Ограничения перед публикацией

Полнота спортивных результатов ограничена локальной выборкой. Wikimedia может ограничивать внешний трафик. Интерфейс показывает резервные изображения, а атрибуция сохраняется, но стабильность CDN нужно оценить на стенде. Для публичного трафика настройте лимиты на прокси для поиска, графа и оптимизатора изображений, мониторинг ошибок, диска и резервных копий. Страницы и API проверены на локальной сборке. Нагрузочные характеристики, доступность на физических устройствах и публикация в поисковиках зависят от выбранной среды.
